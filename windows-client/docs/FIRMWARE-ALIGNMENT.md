# Windows 客户端与 ESP32 接口对齐记录

更新日期：2026-10-16。本轮只修改 Windows 项目，不修改、构建或烧录 ESP32 固件。以下记录将“已确认的产品行为”“现有 GATT 能力”“仍需固件配合的能力”分开，避免界面上保存成功被误认为设备已经实现。

## 已确认的控制分工

PC 读取并上报电脑真实传感器数据。ESP32 根据温度和 speed curve 算出目标 RPM，再由 ESP32 执行转速闭环。Windows 端的曲线插值仅用于编辑器验证和预览，不驱动 PWM，也不周期写入目标 RPM。

温度来源默认取 CPU/GPU 较高值，允许用户选择 CPU 或 GPU。数据失效时先保持最后转速；连续 10 秒没有有效温度后，设备应进入 20% PWM 怠速。该定时器必须在 ESP32 侧执行，Windows 断连后无法发出补救命令。

目前客户端能保存、导入及导出这些偏好；现有固件没有对应配置接口，因此客户端不会宣称已经上传曲线、温度来源或失联策略。

## 需要新增或明确的接口

| 项目 | 现有能力 | 待对齐内容 | 客户端当前处理 |
|---|---|---|---|
| 温度 → 目标 RPM 曲线 | `fan_rpm` 的 WRITE 只能写一个目标 RPM | 曲线的特征、UUID、点数上限、编码、版本、读回验证、持久化及应用时机 | 本机编辑及 JSON 导出，未编造新 UUID |
| 温度来源 | 已有 CPU/GPU 温度两个 double 上报特征 | 默认 MAX、CPU、GPU 的配置接口；MAX 模式一路温度缺失时的规则 | 保存用户选择，实际上传待对齐 |
| 温度有效性和超时 | 现有结构体只缓存数值，没有客户端可查询的有效期协议 | 有效温度判定、最后有效时间、上电无数据行为、10 秒超时后 20% PWM；保护适用 AUTO 还是所有模式 | 缺失传感器不上报，不用 0 或演示温度补位；不假装实现固件保护 |
| 目标 RPM 的范围及 0 | 现有 WRITE 是小端 `uint32` | 风扇物理上下限、0 表示停转还是其他语义、超范围反馈 | 调试输入按 UInt32 编码，实际硬件范围未确认；场景曲线为本地示例 |
| RAM/VRAM 的上报单位 | 四个特征均为小端 double | 字节、MiB、GiB 或其他单位仍未收到确认 | 默认 `Unspecified`，不发送四项内存数据；本地可正常显示 MiB/GiB |
| 风扇配置掉电保存 | 风扇模式、PWM、目标 RPM 能写；不能据此证明全部已落盘 | 哪些字段需要保存、寿命策略、重启读回 | 不标注“设备永久保存成功” |
| 多设备同时通信 | 固件最大连接数为 3，但连接后停止广播 | 多连接广播策略、手机/PC 配置冲突优先级 | 本轮 TODO，不作为验收完成项 |
| 设备启动标识 | 现有接口没有启动计数器或 boot ID | 区分重连、ESP 重启及 UI 重新打开 | 同步询问按新的物理连接处理；重新打开 UI 本身不应被当成 ESP 重启 |

客户端会对有真实温度值的 CPU/GPU 特征保留最多 5 秒一次的心跳，即使数值未变化也重新发送。其他指标按 diff 跳过不变值。该心跳为后续 10 秒固件超时保护留出余量，当前并不能让固件自动获得 watchdog 功能。

## 内置风扇数组的已确认含义

`laptop_fan_used` 和 `laptop_fan_speed` 均为 5 个小端 double，共 40 字节，表示电脑内置风扇，与底座风扇分开。

`fan_used[i] = 1.0` 表示该槽位确实装有风扇，`0.0` 表示没有安装。已经安装但停止转动的风扇仍为 `1.0`，其真实 RPM 可以是 `0.0`。没有安装的 RPM 槽位填 `0.0`。已安装但无法读取 RPM 时，不得伪装成零转速；当前整项 `fan_speed` 暂停上报。

默认按检测到的风扇传感器标识稳定排序；未检测到传感器不等于电脑没有风扇。客户端提供手动数量配置的数据模型，用户可按实际机器指定数量；是否能够对应到所有真实 RPM 仍取决于硬件监控支持。

## 已有 27 个特征的处理边界

UUID 和属性的唯一来源是 `SmartFan.Core/Protocol/ProtocolCatalog.cs`，编解码与校验集中在 `PacketCodec.cs`。

- `fan_mode` 为 4 字节小端 int，合法值 0/1/2。
- `fan_pwm` 为 1 字节 0～100。现有读回恒 0，不作为写入成功的精确读回证明。
- `fan_rpm` 没有 READ；NOTIFY 是实测 RPM，WRITE 是目标 RPM，两者不能相互等同。
- 灯效模式为 0～8。刷新周期只允许 10/20/50/100/200 ms，属于会话参数，不写入持久化场景；亮度为 0～255。
- 八个灯效配置使用精确长度、RGB 顺序、小端时长和浮点布局。自定义呼吸先放所有 RGB，再放所有时长；最多 9 色。环绕配置严格为 22 字节。
- 配置写入使用明确的“应用/同步”操作，避免拖拽中反复写 Flash；支持 READ 的写入会做读回验证。两个风扇接口的已知限制会单独显示。
- 启用演示数据是手动操作，演示数据不会进入真实遥测，也不会参与真实设备控制。
