# 组件拖动与底部编辑优化

此前卡片位置由四舍五入后的网格坐标直接决定，鼠标移动不足半格时卡片不动，越过阈值则跳一格；同一格内的每次鼠标移动仍重新执行布局求解。邻居换位动画以旧的目标位置为起点，快速改变方向时可能从错误的位置重新开始。

现在把连续指针显示与离散落点计算分开：

- 移动和缩放期间只更新当前卡片的渲染平移/缩放，使用手势期间的临时位图缓存，卡片内部不随每个鼠标消息重新测量。松手时再落实最终尺寸并吸附。
- 同一格内不求解布局；同一次手势已计算过的格子直接复用结果。无效落点也持续跟手，松手回到最后一个有效落点。编辑模型在松手时才更新，文件仍需点击完成保存。
- 其他卡片换位，以及松手吸附，从当时实际显示的位置开始 160 ms 缓动。动画结束清理时钟和临时缓存，不增加常驻渲染循环。
- 正常桌面使用整个主页工作区的宽高，取消固定方格造成的左右留白。编辑时全桌面以中心为基准等比缩小，底部出现约 100 像素高的两行操作栏；菜单向上展开。选中其他卡片不会重启桌面缩放动画。
- 用户主动留下的空槽位仍然保留，编辑模式也不会自动改写原来的排布。
- 编辑模式的拖动层覆盖整张卡片，数值、图表、滑条、按钮及内边距都能开始移动；右下角缩放手柄位于拖动层上方，仍只负责尺寸。组件标题保持显示，右上角编辑按钮在编辑期间隐藏，退出后恢复普通控件交互。

回归检查涵盖：1000 次格内指针更新的布局求解次数为 0；小数像素移动；重复格子缓存；无效落点；连续缩放及锁定比例；卡片内部测量次数不随拖动增加；动画中途换目标的连续性；实际 Dashboard 手势路径的松手、取消及窗口尺寸变化；底部面板的居中、占用与向上菜单。这些是逻辑和 WPF 行为检查，不作为整机帧数测量。

整卡拖动另外使用屏幕外真实 WPF 窗口进行输入命中检查：逐张验证卡片中心、标题及四侧留白均命中移动 Thumb，右下角命中缩放 Thumb；风扇模式、PWM 滑条及应用按钮位置在编辑时全部命中移动层，退出编辑后滑条和模式选择恢复原控件命中。检查不会发送真实设备命令。
