# 风扇组件与传感器检查

风扇组件根据所选模式切换内容。手动模式显示 PWM；自动模式显示本机场景的温度来源和当前温度，并提供进入温控曲线编辑器的入口；全速模式显示发送全速请求的说明。修改选项只是本机草稿，点击“应用风扇设置”后才通过既有接口发送模式，手动模式另发送 PWM。

自动模式的本机温度预览沿用场景中 CPU、GPU 或两者较高值的设置。后台遥测分别上报 CPU、GPU 原始温度，目前没有温度来源选择或曲线的固件上传特征，因此界面明确把这些设置称为本机预览。演示数据和已过期的数据不显示为真实调速输入。曲线目前仅用于本机编辑、导出与预览，客户端不执行调速闭环，也不把曲线入口呈现为已经上传固件。曲线上传和设备自动控制接口仍由后续固件对齐。

传感器窗口默认只读取一次，可以手动刷新，也可以勾选每 2 秒实时刷新。窗口请求的是现有后台的传感器枚举接口，不建立第二个采集器；关闭窗口或取消勾选即停止请求。自动刷新不写入重复的成功日志；相同的连续失败只记录一次错误。读数保留原始单位，缺失值不转为 0。

“主页采用”列和浅色背景依据后台 `TelemetrySnapshot.SensorNames` 返回的精确传感器标识显示。该列只标出后台明确报告的来源，不根据相似名称猜测。内置风扇属于电脑硬件传感器，散热底座的 RPM 仍是独立的 ESP32 通知。后台采样时间、数据有效性和传感器列表刷新时间分别显示。

实时刷新复用同一个行对象，因此读数更新不会重建列表、清空搜索或丢失选中行。硬件清单发生变化时重新应用筛选；失败时保留上次结果并显示错误状态。窗口关闭后忽略迟到的异步结果。

离线检查入口为 `FanModeAndLiveSensorChecks.Run`，使用注入的后台回调和屏幕外窗口验证模式内容、过期与演示状态、来源标记、实时刷新开关、行选中状态和定时器清理，无真实硬件读取或设备写入。
