# 2026-10-17：主页、传感器与交互调整

## 本次边界

本次修改 Windows 客户端。主页的运行日志已移至独立的“运行日志与诊断”窗口，入口位于高级设置和接口自检。日志目录、导出和短时流畅度测量集中在该窗口，关闭窗口会解除日志事件订阅。

主页使用内置组件注册表和明确的 `DashboardTelemetryData` 展示契约。CPU/GPU 温度、使用率可以单独或组合使用，内存、电脑内置风扇摘要和底座 RPM 各有组件；组件不访问 BLE、硬件监控器或 MainViewModel 的私有实现。当前不是第三方插件加载系统，也没有实现拖拽自定义布局。主页继续在最小支持窗口内一屏展示。

显示单位在展示层转换：°C/°F、MiB/GiB 的值、标签和精度一起更新，原始遥测仍保留摄氏度和 MiB，不改变发给 ESP 的协议数据。

## 字体与交互

正文、参数和数值统一 Normal，标题统一 SemiBold。界面和绘图都跟随同一个字体资源及中文回退；日志和原始协议 HEX 另用等宽字体。导航选中状态不再切换字重。

滑条由原生 Track/Thumb 即时更新数值，动画仅作用于圆形拇指的光圈和缩放；减少动画设置生效，不为装饰启动持续渲染定时器。亮度和 PWM 保留整数步，透明度等连续参数不使用整数跳变。输入框、下拉框、复选框和设备选择项统一圆角。

扫描设备区使用明确的标题列、操作列和垂直居中布局，按钮高度一致，保留地址/RSSI 的只读绑定。

## 传感器查看

高级设置提供独立“硬件传感器”窗口，首次打开自动从现有后台读取，支持手动刷新及搜索。表格列出硬件、传感器名称与类别、真实值和原始单位。真实 0 与无读数分开；空结果、正在读取、筛选无匹配和失败分别提示。刷新失败保留旧结果并标注，关闭窗口后忽略晚到的数据，没有额外采样器或常驻刷新任务。

CPU 温度的实际来源、失败原因、后台权限和采集库状态传到高级设置及传感器窗口。最初标准采集缺 PawnIO；继续调查后，通过本机 ASUS 专用只读接口实测取得 CPU 温度，以及 CPU/GPU/辅助三颗内置风扇转速。已接入独立后备来源，仅匹配经过验证的 G615LRG 机型；有效标准 CPU 读数仍优先，GPU 沿用 LHM。ASUS EC CPU 温度不冒充 CPU Package，本机不必为了这一来源另装 PawnIO。最终发布后台、主页和 ESP 温度写入读回均已实测，具体时刻与原始报告见 [CPU 诊断与验收](CPU-TEMPERATURE-DIAGNOSTICS.md)。

主页明确写“散热底座风扇 · ESP32”。其 RPM 来自 ESP 通知，电脑内置风扇则来自本机 Fan 传感器。当前固件 `fan_get_rpm()` 返回 0～99 随机通知测试值，客户端没有缩小 RPM。本次保留固件测试代码。[RPM 来源核查](RPM-DIAGNOSTICS.md)。
