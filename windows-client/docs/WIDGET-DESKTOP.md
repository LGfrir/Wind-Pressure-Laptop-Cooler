# 主页组件桌面

主页右上角点击「编辑组件」，或点击某张卡片右上角的「⋯」，即可编辑。

- 编辑时拖动组件的任意位置移动，包括数值、图表、控件和内边距；右下角手柄优先用于改变宽高。拖动时连续跟随鼠标，松手后吸附到网格；跨格时才计算其他组件的位置。无法容纳的修改不会覆盖上一个有效布局。退出编辑后，内部控件恢复正常操作。
- 编辑时整块桌面从中心等比缩小，底部出现紧凑操作栏；正常浏览铺满主页工作区，不为侧边面板留空。底部可以精确选择宽度、高度，以及自由比例、1:1、2:1、1:2，选择菜单向上展开。锁定比例时，实际卡片保持对应宽高比，窗口改变尺寸后仍然有效。
- 缩小后的桌面带有强调色轮廓及浅色外圈，标出完整可放置范围；桌面底色和外围遮罩帮助区分照片背景，边框随桌面一起缩放，不会拦截拖动。
- 数值组件支持推荐、大号数值、进度条、仪表盘；CPU/GPU 合并组件也支持切换，窄长卡片会把两项数据纵向排列。列表、曲线和控制组件保留各自适合的交互。
- 底部第一行可先选组件内容、宽、高和比例，再添加；「可添加 / 放不下」会实时提示当前尺寸能否放进空位，放不下时禁用添加。新增组件不挪动已有组件。单项数值最小 2×2 格，底座 RPM 保持 3×2，CPU/GPU 组合与内置风扇保持 4×3，曲线与控制保持 5×3。各组件会过滤无法满足最小尺寸的比例。
- 添加列表优先展示「CPU 温度＋使用率」「GPU 温度＋使用率」，也保留温度、使用率、频率、电压、内存等单项。第二行的内容选择器可以原地把单项换成组合，保留 ID、位置及足够的原尺寸；例如 8×3 的 CPU 温度卡可直接换成温度＋使用率，无需移除重建。放不下的替换不会覆盖原组件。
- 选择组件后，方向键移动；Ctrl + 方向键改变尺寸；Delete 移除。底部也提供同等操作。
- 「完成」把布局保存到 `settings.json` 的 `Dashboard`；「取消」恢复进入编辑前的布局；「重置」先恢复推荐布局到草稿，完成后才保存。重新打开时必须读取同一份实际配置，本轮发现启动上下文差异并已完成原生保存与恢复验收，证据见下文。

桌面固定在一个视口内，调整窗口时整体适配，无需在主页上下翻页。尺寸以 16 × 8 网格保存；卡片间留空，锁定的物理宽高比不因间距被拉伸。编辑时禁用组件内部设备操作，避免拖动时误发 PWM。布局保存仅写本地设置，不同步 ESP，不重配后台。

组件共享已有后台的采样数据。添加重复组件不会新建硬件采样器；转速历史保留最近五分钟的当前会话数据，重排或切换显示方式不会清空它。正常退出并重启后，历史重新开始采集。

布局和显示模式参与现有 JSON 导入/导出。旧版 v1 设置没有 `Dashboard` 时，自动使用推荐桌面，并保留原有壁纸、主题和场景。导入时拒绝越界、重叠、未知组件、重复 ID、未知显示方式和比例不匹配的布局。

实现入口：`DashboardLayout.cs` 定义持久化模型和网格放置；`DashboardView` 负责工作台和编辑草稿；`DashboardDragSession` 分离连续指针移动和离散落点计算；`DashboardWidgetMotion` 负责渲染变换、临时缓存与连续换位动画；`DashboardWidgetRegistry` 负责数值组件组合；`DashboardTelemetryData` 接收现有采样的展示投影。后续增加组件需要同时注册持久化白名单与组件工厂。

验证包括旧设置兼容、JSON 往返、保存失败保留草稿、取消还原、占用位置重排、容量保护、最小窗口编辑器不重叠、准确宽高比、实时数据与单位绑定，以及已有接口解析/滚轮回归。此前版本的鼠标验收曾因窗口激活失败未完成；本次已在 C 盘部署版本实际拖动、缩放，验证菜单向上展开和取消恢复。详细记录见 [拖动与底部编辑优化](WIDGET-MOTION.md)。

2026-10-18 添加预设与边框验收：518 项 WPF 检查、196 项服务断言、48 项 IPC 断言通过。最小视口额外检查 2×2 进度卡的数值、单位及 8px 进度条均位于真实内容边界内，4×3 组合卡保留两项标签。实际窗口将用户已保存的 8×3 CPU 单项原地换为组合并保存，七个组件中仅 CPU 的 Kind 改变，原位置、尺寸及其他六项完全一致。另临时缩小电压卡腾出 2×2 空位，实际验证待添加宽度 3 时提前禁用添加、改为 2 后成功插入；随后取消该次测试，保留正式七组件布局。前端与共享程序集均已部署到 C 盘本地目录，前端启动后的日志为 0 Warning / Error；后台因共享布局模型更新完成一次正常退出与重启，`agent.json` 哈希保持不变。

2026-10-18 后续迭代增加以下操作与显示方式；此处描述功能，不代替本轮最终部署验收记录：

- 编辑支持最多 60 步撤销，快捷键为 Ctrl + Z；Ctrl + Y 或 Ctrl + Shift + Z 重做。一次完整拖动或缩放计为一步，选择组件和无效操作不制造历史记录。撤销后开始新修改会清除原先的重做分支。
- 未完成的有效编辑自动写入设置目录中的 `dashboard-draft.json`，与已保存的 `settings.json` 分开。重新打开前端时，原始布局仍匹配才恢复为编辑草稿；点击完成仍需正常保存，取消则还原原布局。已导入或另行改变的布局不会被旧草稿覆盖，无法解析的草稿保留文件供检查。
- 拖动或缩放到无法容纳的位置时，红色轮廓标出当前无效位置，浅色轮廓保留最后有效落点；底部说明松手后的实际结果。松手后返回已标出的有效位置，可通过撤销退回上一步。
- 组件库使用缩略预览选择内容，并提供紧凑、标准、宽幅预设；添加前在桌面标出候选落点。当前尺寸放不下时，会尽可能推荐可容纳的较小尺寸，点击建议可应用；现有组件保持原位置。
- 数值和仪表盘根据实际尺寸调整布局。紧凑卡优先显示数值与单位，空间充足时加入内存容量、最近峰值及短期趋势；CPU/GPU 型号、采集来源 ID 和长诊断说明放在悬浮提示及传感器窗口，主页不堆叠这些文字。信息来自同一个后台。趋势保留当前会话最近五分钟、最多 600 个样本，来源或设备切换时重新开始，采样中断保留断点。有效进度和仪表弧线使用短暂显示过渡，实际绑定数值即时更新。
- 底座风扇卡随手动、自动、全速模式切换内容。自动模式明确显示本机温度预览和曲线入口；温度来源与曲线上传接口仍待固件对齐，不表示设备已经采用本机曲线。断连、演示模式和操作进行中会禁用应用按钮，操作状态显示在卡片内。
- 数据有效性独立于传感器是否存在和 ESP 是否连接：区分等待、实时、已过期及后台中断。过期后不把旧数值继续呈现为当前读数，保留最后采样时间与说明；CPU/GPU、内存和电脑内置风扇共享这一状态，底座 RPM 按自己的通知时间判断。硬件传感器窗口可选择每 2 秒刷新，标出主页实际采用的来源，并显示后台采样时间与有效性。

风扇和传感器窗口的详细边界见 [风扇组件与传感器检查](FAN-CONTROL-SENSOR-INSPECTOR.md)，CPU 频率、电压的本机复核见 [2026-10-18 传感器记录](SENSOR-AUDIT-2026-10-18.md)。
