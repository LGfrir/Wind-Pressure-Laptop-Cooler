CPU 频率和电压当前缺失发生在后台采集阶段，前端拿到的就是空值。温度能通过 ASUS EC 读到，使用率也有来源，因此出现“温度、使用率正常，但频率、电压不可用”的组合。

LibreHardwareMonitor 0.9.6 的 Intel CPU 实现使用 PawnIO 的 `IntelMsr` 模块访问硬件寄存器；本次后台报告该驱动未安装、设备不可访问，说明这一前提还没有满足。对应代码可查看 [IntelCpu.cs（v0.9.6）](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/blob/v0.9.6/LibreHardwareMonitorLib/Hardware/Cpu/IntelCpu.cs)。

PawnIO 官方站点提供经过数字签名的官方版本：[pawnio.eu](https://pawnio.eu/)。如后续决定启用该依赖，应在安装后明确重启后台，再重新枚举传感器核对实际结果。前端连接到已经运行的后台时，不会改变那个后台进程的权限；仅以管理员身份重新打开前端，也不会自动提升原有后台。

驱动可访问是标准硬件采集通道的前提，不能据此承诺所有机型都能返回 CPU 电压。电压还取决于处理器、固件和采集库是否提供适用的传感器。当前没有电压项，安装依赖后的结果需要实测确认。

本次没有安装驱动、提升后台权限或修改 Windows 安全设置，也没有修改 ESP32 固件。客户端保持缺失值为空，不以 Win32/WMI 的额定或汇总频率补作实时核心频率；这类数值不能替代逐核心传感器的实际测量。重新核对时应同时记录后台权限、驱动设备访问状态、各核心频率的原始值，以及是否真正出现 CPU 电压传感器。

传感器窗口现支持可选的每 2 秒实时刷新，并标出后台明确报告的主页来源。它可以帮助区分“选错传感器”“后台没有有效值”和“数据已经过期”，但不会自行安装驱动或增加一个独立采集器。操作说明见 [风扇组件与传感器检查](FAN-CONTROL-SENSOR-INSPECTOR.md)。
