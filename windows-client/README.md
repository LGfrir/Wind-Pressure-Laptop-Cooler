# SmartFan Windows 控制端

基于 .NET 10 / WPF / Windows 原生 WinRT BLE 的散热底座控制面板。前端和后台是两个独立应用：关闭控制面板，后台仍继续保持蓝牙连接、读取电脑传感器并按已保存的选择上报数据。

## 运行

构建需要 Windows 和 .NET 10 SDK。当前电脑推荐发布并部署到用户本地运行目录：

```powershell
.\tools\publish.ps1 -Deploy
& "$env:LOCALAPPDATA\SmartFanNext\app\SmartFan.exe"
```

前端首次启动会接入或启动 `SmartFan.Agent.exe`。已有后台时先接入，不重复弹 UAC；没有后台、已安装 PawnIO 且前端为普通权限时，只为后台申请管理员启动。前端保持普通权限。取消管理员提示会明确报错；已有后台拒绝访问时提示更新或关闭旧后台，不反复启动新实例。发布包中的两个 exe 应放在同一目录。`-Deploy` 的运行目录为 `%LOCALAPPDATA%\SmartFanNext\app`，配置仍保存在原有 AppData 目录，不会随应用更新覆盖。

这台电脑把 G 盘项目路径判为 Internet 区。从 G 盘 `bin` 或 `artifacts` 直接运行可能出现安全警告，并且已有 A/B 测试发现无法接入后台；修改工作目录或仅使用 `--data-dir` 不能修复这个进程启动位置问题。Rider 调试时也应运行部署到 C 盘的程序。未修改 Windows 信任区域、目录权限或 UAC 策略；2026-10-19 另修正了应用自身命名管道的同用户权限，支持普通前端连接管理员后台。

发布 Windows x64 自带运行时的免安装包：

```powershell
.\tools\publish.ps1
```

输出目录为 `artifacts\win-x64`，包含 `SmartFan.exe`、`SmartFan.Agent.exe` 和运行时依赖，目标电脑不需要另外安装 .NET。应将发布包放在正常的本地运行目录。直接运行 `SmartFan.exe` 使用正常的用户配置目录；运行 `Start-SmartFan-Portable.cmd` 则明确使用包内的 `data` 子目录。该启动器不改变 exe 的安全区域，不能解决本机从 G 盘启动的限制。

也可自选便携配置目录：

```powershell
& "$env:LOCALAPPDATA\SmartFanNext\app\SmartFan.exe" --data-dir 'D:\SmartFanData'
```

便携模式不读取旧版外观偏好，也不会改动默认 AppData 配置。如果相同用户的后台已经运行，前端会附着现有后台并显示它实际使用的 JSON 路径；需要改用另一个后台配置目录，应先明确停止现有后台再启动。

也可以只启动后台，由它直接读取 JSON 中的启动参数：

```powershell
& "$env:LOCALAPPDATA\SmartFanNext\app\SmartFan.Agent.exe" --config "$env:APPDATA\SmartFanNext\agent.json"
```

默认只读取本机硬件，不自动连接 ESP，也不上报。需要连接时，在控制面板扫描选择设备，或用地址/最近设备直接连接。连接新的设备会询问是否同步本机场景；明确开启“自动上传”后，由后台在新的物理连接建立时同步支持的字段。

新安装默认关闭窗口就退出前端。可选最小化到托盘；这与后台是否继续运行无关。“后台登录自启”只启动后台，不弹出前端。需要停止后台，使用界面中的明确操作或：

```powershell
& "$env:LOCALAPPDATA\SmartFanNext\app\SmartFan.Agent.exe" --stop
```

可用 `--probe --output .\agent-status.json` 查看正在运行的后台 PID、权限、采样次数和最近快照。更多命令见 [架构与进程说明](docs/ARCHITECTURE.md)。

登录自启目前仍是 `HKCU\...\Run` 的普通权限启动，没有创建提升权限的登录任务；本机当前未启用该选项。它不能保证 PawnIO 的管理员访问能力。如果以后由登录项先启动了普通后台，前端会优先附着，不会自行替换或提升那个进程。

## 功能

主页现在是可编辑的组件桌面：添加/移除、拖动、调整宽高、锁定 1:1 / 2:1 / 1:2 比例，并为数值组件选择进度条、仪表盘或数值显示。「完成」后布局保存到本机，也包含在完整 JSON 导入/导出中。本轮已在原生启动上下文验证十组件布局的保存与重启恢复，详见 [组件桌面操作说明](docs/WIDGET-DESKTOP.md)及[本轮验收记录](docs/DESKTOP-REFINEMENT-2026-10-18.md)。

组件编辑进一步支持最多 60 步撤销/重做、独立 `dashboard-draft.json` 草稿恢复、无效落点红框与实际落点提示。添加组件可以先看缩略预览、选择尺寸并查看候选位置；放不下时推荐可用的较小尺寸。数值卡按大小显示关键数值、单位、内存容量、最近峰值和短期趋势；CPU/GPU 型号、来源 ID 和长诊断说明移至悬浮提示与传感器窗口，主页减少文字堆叠。进度与仪表弧线带显示过渡。以上操作仍只编辑本机桌面。

风扇卡根据手动、自动、全速模式展示相应内容，自动模式的曲线与温度来源明确标作本机预览。主页区分数据正常、缺失、过期和后台中断；过期读数显示最后更新时间。硬件传感器窗口提供可选的每 2 秒实时刷新、主页采用来源高亮和后台采样时间，复用已有后台且关闭窗口即停止列表刷新。详见 [风扇组件与传感器检查](docs/FAN-CONTROL-SENSOR-INSPECTOR.md)。

- 设备扫描、地址直连、最近设备、重连、配对状态及接口自检；每行可展开查看载荷的中文字段、单位、类型及字节偏移，保留原始 HEX 对照。[解析说明](docs/DIAGNOSTIC-DECODING.md)
- 风扇模式、手动 PWM、目标 RPM 调试、实时 RPM 与历史曲线。
- 九种灯光模式、亮度、五档刷新周期、八种灯效参数编辑器，明确应用后才写设备。
- 可拖拽的温度 → RPM 曲线、多个场景、JSON 备份与导入。
- 实时 CPU/GPU/内存监控、传感器选择、上报项开关及频率配置。
- 四套主题与跟随系统、自定义强调色、壁纸裁剪、字体与单位、托盘及后台登录自启。
- 矢量品牌图形、悬停与页签切换过渡、平滑滚动及完整的颜色编辑。

真实读不到的传感器显示“不可用”。演示模式必须手动开启，演示数据不会进入真实设备控制或遥测。仪表盘分别显示电脑内置风扇与 ESP32 底座风扇；本机 ASUS G615LRG 的只读 EC 来源继续作为温度及内置风扇后备。硬件传感器窗口复用现有后台，支持筛选、手动刷新及可选实时刷新。

## 配置与边界

设置目录为 `%APPDATA%\SmartFanNext`：`settings.json` 保存前端外观和场景，`agent.json` 保存后台启动及上报参数。旧版 `%APPDATA%\SmartFan` 保留，仅读取可迁移的外观偏好。

2026-10-18 验收发现工具进程与手动启动的前端存在配置视图差异：工具打开名义上的 Roaming 配置时，文件句柄实际指向 Codex 包的 `LocalCache\Roaming\SmartFanNext\settings.json`；该视图为十组件，原生前端导出则为另一份九组件配置。因此不能仅用工具侧 `%APPDATA%` 文件内容认定前端实际读取的布局。现已增加启动加载路径、实际打开路径及组件数量日志，保存布局时也记录实际路径与数量；没有修改系统虚拟化策略、权限或配置架构。已通过原生前端导出并仅合并 `Dashboard` 恢复十组件。18:27、18:31 经 Explorer 两次启动 C 盘正式程序，均无安全提示，加载日志确认实际读取 `C:\Users\zen\AppData\Roaming\SmartFanNext\settings.json`、路径解析成功且为十组件；18:30 点击「完成」保存到同一路径。重启导出布局的 ID、内容、位置、尺寸、显示方式及比例与原备份逐项一致。其他配置保持原生导出内容，仅正常保存了窗口 Left/Top 坐标。详见[本轮原生验收记录](docs/DESKTOP-REFINEMENT-2026-10-18.md)。

早期从 G 盘启动编译后 exe 时曾出现 AppData 写入或命名管道访问失败，而 dotnet 宿主行为不同。交接测试已验证从 C 盘本地目录运行可正常接入后台并写入日志。程序不修改目录 ACL，不静默更换数据目录，也不将便携配置目录当作绕过 G 盘进程限制的方法。

PC 只负责上报温度，ESP32 负责由曲线计算 RPM 和实际调速。曲线上传、温度来源配置及“10 秒无有效温度后 20% PWM”尚无固件接口；当前可本地编辑和保存，不能当作已经上传或执行。RAM/VRAM 的设备单位未确认，默认不发送四项内存数据。完整记录见 [固件接口对齐清单](docs/FIRMWARE-ALIGNMENT.md)。

2026-10-16 最初的开发板只读记录有五项非法载荷或 ATT 错误；该记录是历史证据。此后 DSH 已重新烧录当前源码，当前设备应重新验收，不能直接沿用旧失败结论。该开发板不是最终 PCB，也不能据此验收真实风扇和灯条的物理效果。

## 错误日志

- 前端：`%APPDATA%\SmartFanNext\frontend-logs\smartfan-yyyyMMdd.jsonl`，`detail` 字段包含完整异常堆栈。
- 后台：实际 `agent.json` 同目录的 `logs\agent-yyyyMMdd.jsonl`。
- 自选 `--data-dir`：前端日志改为所选目录的 `frontend-logs`，后台目录以界面显示的实际配置路径为准。

在“高级设置”或“接口自检”打开独立的“运行日志与诊断”窗口，可以查看近期摘要、打开前后端日志目录、导出前端日志和测量短时界面流畅度。主页不显示日志面板。2026-10-17 的扫描列表绑定故障、实际日志位置和修复验证说明见 [SCAN-BINDING-FIX.md](docs/SCAN-BINDING-FIX.md)。
